Secure every layer of the platform.

From the hardware and firmware that start a computer, to the virtual machines that run on top of it, learn how platforms are built and how they are attacked and protected.

Explore the layers

Chain of trust

Each boot stage checks the next one before handing over control.

  1. Root of Trust TPM / firmware key
  2. Firmware checks the signed bootloader
  3. Bootloader checks the OS kernel
  4. OS verifies drivers and applications

If any step fails, boot stops or an alert is raised.

Layers of a computing platform

Every layer has a job, and every layer has its own attack surface.

Hardware

Physical components: CPU, memory, storage, and peripherals. Attack surface: side-channel attacks and physical tampering, where an adversary gains direct, hands-on access to the hardware hosting a platform.

Firmware

BIOS/UEFI, device firmware, and initialization processes. Attack surface: BIOS/UEFI rootkits and firmware backdoors.

Operating system (OS)

Manages hardware, runs applications, and enforces security. Attack surface: privilege escalation and kernel exploits.

Applications

Software that provides user-level services. Attack surface: malware and unpatched software vulnerabilities.

Mobile, desktop, cloud and virtualization

The distinction lies in how hardware components, CPU instruction sets, OS kernels, and security boundaries are layered together.

Mobile (Android / iOS)

Optimized for portability and battery life, with tight integration of hardware and software. App sandboxing and stricter permissions.

Desktop (Windows, macOS, Linux)

Higher performance and flexibility, and a broader software ecosystem. More customization, but a larger attack surface.

Cloud platforms

Abstract physical resources and provide services on demand (Amazon Web Services, Azure). Security relies on a shared responsibility model.

Virtualization platforms

Hypervisors enable multiple VMs on one physical machine. This increases resource efficiency but adds risks such as VM escape and misconfigurations.

Cloud vs. virtualization

Virtualization is the core technology, while cloud computing is the service model built on top of it.

Trusted Platform Module (TPM)

A hardware-based security chip that provides a Root of Trust for a computing platform.

What it is

A security chip that functions independently of the main CPU and OS. It ensures secure storage, encryption, and attestation.

Keeps secrets safe

Stores digital keys, certificates, and passwords in a secure chip so hackers cannot easily steal them. Think of it as a tiny safe built into your computer.

Starts the computer safely (Secure Boot)

When you turn on your computer, the TPM checks that the system has not been tampered with before letting it load.

Blocks hidden startup attacks

Hackers sometimes sneak malware in before Windows or Linux even loads. The TPM helps stop these firmware and boot-level attacks.

UEFI

The Unified Extensible Firmware Interface is the modern replacement for BIOS, the firmware that starts your computer. It is the first program that runs at power-on, initializes the hardware (CPU, RAM, drives), then hands control to the OS. It is the bridge between hardware and OS.

Chain of trust

Each stage of the boot process checks the integrity of the next before handing over control, so all software is verified, unmodified, and trusted from the moment power hits the motherboard. The steps: (1) Root of Trust, the TPM or firmware key, is the immutable baseline. (2) Firmware checks the bootloader, which must be signed. (3) The bootloader checks the OS kernel. (4) The OS verifies drivers and applications. If any step fails, boot stops or alerts are raised.

TPM versions

The specifications are governed by the Trusted Computing Group (TCG). TPM 1.2 offers basic crypto support (SHA-1, RSA). TPM 2.0 offers stronger algorithms (SHA-256, ECC) and flexible authorization, and is required for Windows 11 and modern enterprise-grade security solutions.

Security benefits

Protects against rootkits and bootkits, key theft, and unauthorized firmware changes. It provides hardware-enforced trust instead of relying on software-only security.

Limitations

Requires hardware support (not all devices have it). If the TPM fails, access to encrypted data may be lost. It cannot stop OS-level malware once the system has booted, and physical attacks on the chip (an advanced threat) are still possible.

Virtualization

A technology that lets multiple virtual machines (VMs) run concurrently on a single physical server.

Core ideas

Consolidated hardware: one physical server hosts many virtual environments. Isolated environments: each VM runs independently with its own OS and applications. Maximized utilization: makes the most of the underlying hardware.

Types of virtualization

Server: many virtual servers on one physical server (most common). Desktop: virtual desktop infrastructure (VDI) and remote access. Network: virtual networks independent of hardware. Storage: pooled storage from multiple devices. Application: apps run in isolated environments.

Types of hypervisor

The hypervisor is a software layer that allocates physical resources to VMs, ensuring isolation and efficient operation. Type 1 (bare-metal) runs directly on hardware with high performance and security (VMware ESXi, Microsoft Hyper-V). Type 2 (hosted) runs on a host OS (VirtualBox, VMware Workstation).

Benefits

Cost reduction: no millions spent on idle physical servers. Agility: deploy, scale, adapt, or recover quickly. Disaster recovery: restore software and data fast after an outage. Improved management: a single operational interface. Testing and compatibility: simulate many operating systems, screen sizes, and hardware setups.

Popular platforms

Enterprise: VMware vSphere, Microsoft Hyper-V, Citrix XenServer, Red Hat Virtualization. Desktop and development: VMware Workstation/Fusion, Oracle VirtualBox, Parallels Desktop, QEMU/KVM.

Security of virtual environments

Virtualization adds efficiency, and adds its own risks.

Hyperjacking

An attacker gains control of the hypervisor itself, effectively taking over all hosted VMs. It is dangerous because the hypervisor has the highest privilege level, so attackers can monitor, manipulate, or shut down every VM. Example: a malicious hypervisor installed underneath an existing OS (a "blue pill" attack). Countermeasures: apply regular hypervisor patching, and limit admin/root access with MFA and strict role separation.

VM escape

Malicious code inside a VM breaks isolation and reaches the hypervisor or host. From the host the attacker can control all other VMs, which violates the core promise of virtualization: isolation.

Misconfiguration

Weaknesses caused by insecure administrator settings, not flaws in the hypervisor. Examples: too many privileges for VM users, flat virtual networks without VLANs or segmentation, weak or default management console credentials, and overcommitting CPU and RAM, which can lead to denial-of-service.

VM isolation techniques

Strong separation so each VM acts as an independent system; resource allocation controls (CPU, RAM, storage quotas); access control to prevent unauthorized VM-to-VM access; and snapshot monitoring to detect rollback attacks.

Secure VM networking

Virtual switches control VM traffic, VLANs separate workloads, firewall rules apply per VM or per network segment, and IDS/IPS integration detects malicious VM traffic.

Snapshots and rollback

Snapshots save system state for recovery and testing. Risks: rollback to vulnerable versions and exposure of sensitive data in snapshots. Best practices: encrypt snapshots, monitor and control snapshot creation, and patch and update after a rollback.
